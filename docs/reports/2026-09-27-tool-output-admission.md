## Direct answer

Tool output admission reduced ordinary build progress in a live DeepSeek Harness profile while leaving uncertain test output intact. In the final profile run, a real main model invoked native `bash` on a small, executable acceptance project, and real Jev judged the result. The build tool result delivered to the Agent fell from 8,510 to 2,072 characters, a net saving of 6,438 characters (75.7%), with the final artifact hash preserved. A separate real 180-test run reached Jev, but its omit probabilities were only 0.66–0.71 against the 0.8 default, so all 20,543 characters remained. A failing test preserved its failure evidence, and a complete-log request used the Host's native spill and was successfully read back from the same Session.

These findings follow several distinct experiments. The early Hook runs used real Jev with a scripted main model and deterministic shell fixture. The direct API experiment sent judgment requests without a main model or tool execution. The final profile run used a real main model and real processes. The published [implementation](../../packages/jev/src/output-admission.ts) and [deterministic integration tests](../../packages/jev/tests/output-admission-integration.test.ts) cover the supported Hook and Session paths. The raw live sessions, local profiles, credentials, and machine-bound experiment scripts remain outside this repository.

## Real Jev results before the live profile

The first A–D Hook run recorded 22,191 input and 1,196 output tokens across four Jev calls. Their individual Jev latencies were 462, 682, 281 and 302 ms (1,727 ms summed, not end-to-end wall time). The omit-probability ranges were A 0.42–0.48, B 0.62–0.67, C 0.71–0.75 and D 0.43–0.47. None reached 0.9, so all four original outputs were delivered. Candidate formation protected the unique build result, test summary, failure names, requested login result, and 425 ms slow test. The first B assessment's “PTC program value changed” finding was an invalid comparison of literal and JSON-escaped text; that first real run did not save the structured program value and therefore did not verify it.

The direct API experiment then added verbatim retained evidence with source line ranges and revised the question to ask whether a candidate supplied task-needed information absent from that evidence. The candidate text and order stayed fixed. B had 10/10 candidates at 0.96–0.98; C had 4/4 at exactly 0.90; A had 0/8 at 0.80–0.83; D had 0/10 at 0.70–0.75 under the then-current 0.9 threshold. It recorded 24,326 input and 1,196 output tokens, with Jev latencies of 569, 280, 248 and 317 ms (1,414 ms summed). B's 10,760 and C's 4,620 candidate characters selected by offline simulation were not actual Agent savings: omission markers, retrieval text, and later Host processing were outside that calculation. Retained evidence and question wording changed at the same time, so the experiment cannot isolate their individual effects. C's single response at exactly 0.90 does not establish repeatability.

In the revised Hook run, each of A–D and the negative case N made exactly one real Jev request. The final numbers were:

| Case | Omit probability; candidates at or above 0.8 | Actual net Agent saving | Jev latency | Input/output tokens |
| --- | --- | --- | --- | --- |
| A: 500 build-progress lines | 0.86–0.89; 8/8 | 7,604 / 8,507 characters (89.4%) | 604 ms | 7,277 / 299 |
| B: 180 passing entries, PTC outer logs | 0.79–0.83; 7/10 | 7,443 / 10,837 characters (68.7%) | 337 ms | 7,572 / 373 |

The five calls recorded 33,675 input and 1,569 output tokens. Their 1,864 ms summed Jev latency is not a wall-time or cost measure. A–C saved complete original text before omission, and final Agent input matched the durable Session result. B's saved structured PTC `stdout.text` matched its original program value; the outer logs alone were shortened. C retained each distinct failure, the summary, exit marker, and a source-line reference for the exact duplicate. The explicit complete-log and insufficient-evidence controls made zero Jev calls and delivered the original text.

The original automated acceptance command for that run exited 1 because its then-current criterion required D to save at least 300 characters and 10%. The user subsequently accepted D's conservative behavior: when every omit probability is below 0.8, exact original delivery is the desired result. An **offline review of the saved run**, without another Jev request or test rerun, found A–C above 300 characters and 10%, D exactly original, N's three requested times intact, and both zero-call controls intact. The exit-1 result remains part of the historical record; the updated acceptance is not a claim that the old command was rerun green. D's lower probability than in the direct API experiment cannot be attributed to a single cause: the formal Hook request also carried source reasons, unshown-candidate scope, and Host spill/compaction caveats, with different question wording.

## Live profile and Host output handling

The final profile's build command parsed, transpiled, emitted, hashed and executed 100 generated TypeScript modules, producing 500 counted progress lines. Jev judged seven blocks at 0.93–0.94 in 726 ms (7,173 input / 262 output tokens). The original 8,510-character output was archived exactly; the 2,072-character durable tool result included omission markers and a retrieval hint. The main model's final artifact SHA-256 agreed with the actual build output.

The first 180-test task unintentionally included a word matching the test file's stem; it produced zero Jev judgments and a full 20,543-character durable result. A separate neutral task description then exercised the test-log branch once. Jev judged 18 candidates at 0.66–0.71 in 568 ms (10,935 input / 677 output tokens), adopted none at the default 0.8, and preserved the full 20,543-character Session result with `180 passed`. This demonstrates real branch activation and conservative delivery, not test-log savings in this profile run. A separate real failing Vitest run produced 73 passes and one failure; its 10,052-character Session result retained the assertion, stack, `[exit code: 1]`, and a named 351 ms slow item. It made zero Jev judgments.

For a request to keep complete output, a real file inventory produced 59,890 bytes covering 201 files. Jev made zero calls. The Host's native spill left a 49,931-character durable tool result with a pointer to the full original and an “omitted 10,202 bytes” notice. The spilled bytes matched independently captured command output byte for byte. In a continuation of that same Session, the real main model ran native `bash` once to read the spill file's last line; the recovered file count and both hashes matched the independent preflight. The initial inventory and recovery continuation used two main-model steps each; the continuation did not call Jev. This exercises native spill and recovery, while the build case separately exercises Jev omission. The live run did not produce one tool result that triggered both reductions.

The headless JSON event stream abbreviates long `tool_result` previews near 8 KiB. All delivered-length, summary, exit-marker and omission claims above were checked against the persisted Session `tool/result`, not that preview or the model's final narration alone.

## Scope and verification

The public [Hook implementation](../../packages/jev/src/output-admission.ts), [rules](../../packages/jev/src/output-admission-rules.ts), [retained-evidence assembly](../../packages/jev/src/output-admission-evidence.ts), and [integration tests](../../packages/jev/tests/output-admission-integration.test.ts) are available for independent inspection. The revised Hook round recorded a 16/16 focused integration run and an offline preflight; those are historical results, not tests newly executed for this publication. Ordinary test commands skip the paid real-Jev cases by default. The live profile was an isolated synthetic acceptance project with real compilation, test processes and model calls; it was not a build of a large user repository or a Web UI manual trial.

The paid experiments used a bounded number of requests and external credentials kept outside Git. Their local raw requests, answers, Session captures, shell outputs, profile, and environment-bound scripts are intentionally unpublished. This report contains aggregated observations and a package hash, not enough material to independently replay identical model responses. Model probabilities can vary on repeat calls. These report files contain no credential value, authorization header, local profile location, or live Session identifier.
